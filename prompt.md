Je veux une recherche très large pouvant représenter des dizaines ou centaines de ressources pertinentes.

# 39. NE PAS UTILISER LA POPULARITÉ COMME PREUVE

Une vidéo à 2 millions de vues peut être :

- ancienne ;
- simplifiée ;
- incorrecte ;
- destinée aux débutants.

À l'inverse, une analyse technique peu connue peut être extrêmement pertinente.

Évalue les informations selon :

**fiabilité × fraîcheur × expertise × reproductibilité × concordance avec les données.**

---

# 40. NE PAS CONFONDRE MÉTA ET OPTIMALITÉ ABSOLUE

Lorsqu'un build/perk/playstyle est populaire :

chercher pourquoi.

- popularity ;
- accessibility ;
- consistency ;
- ceiling ;
- tournament usefulness ;
- SoloQ usefulness ;
- SWF usefulness ;
- matchmaking usefulness.

---

# 41. DISTINGUER FACT / HEURISTIC / OPINION

Dans tes notes internes et lorsque cela est utile dans le document, distingue :

### FACT
Mécanique vérifiable du jeu.

### DATA
Observation statistique.

### HEURISTIC
Règle pratique généralement utile.

### EXPERT OPINION
Conclusion d'un joueur expérimenté.

### HYPOTHESIS
Interprétation plausible non confirmée.

### SITUATIONAL
Conseil dépendant fortement du contexte.

Cela est extrêmement important.

# 47. DEFINITION OF DONE

Le projet n'est PAS considéré terminé parce que :

- le document est long ;
- beaucoup de sources ont été consultées ;
- toutes les pages semblent remplies.

Il est terminé uniquement lorsque :

1. la taxonomie a été auditée ;
2. aucune catégorie critique connue n'est absente ;
3. tous les Killers pertinents sont inventoriés ;
4. toutes les maps pertinentes sont inventoriées ;
5. les perks sont inventoriées ;
6. les mécaniques principales sont vérifiées ;
7. les informations sensibles aux patches ont été vérifiées ;
8. les contradictions importantes sont résolues ou explicitement marquées ;
9. les sections avancées contiennent de la décision et non simplement de la description ;
10. au moins deux audits adversariaux ont été réalisés ;
11. les sources sont traçables ;
12. les éléments non résolus sont explicitement listés.

Si ces conditions ne sont pas atteintes :

le statut final doit être :

**NOT READY**

et non :

**COMPLETE**.
